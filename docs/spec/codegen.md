# Code Generation Specification

## `grizzle gen` — typed Go structs from schema definitions

`grizzle gen` reads Go schema definition files (containing `pg.Table(...)`, `mysql.Table(...)`, etc.) and emits `*_gen.go` files with typed Go structs and column handles.

`grizzle gen` must use static parsing or another non-executing schema representation by default. It must not execute arbitrary package initialization code from the target project unless a future explicit trusted-code mode is designed and documented. Static schema input traversal follows the same Go source filesystem/resource-limit contract as file-migration `generate`: canonicalized no-follow roots, regular files only, hardlink/symlink rejection where detectable, source byte/file/AST/declaration/literal caps, context cancellation, redacted diagnostics, and `invalid_path` / `resource_limit` errors.

Same-directory generation is supported for the common `grizzle gen --schema ./db --out ./db` workflow. When the schema input root and generated output root are the same directory, traversal must parse user-authored `.go` files and skip only Grizzle-managed generated files recognized by the exact generated header and `*_gen.go` ownership pattern. It must not skip the entire root. If the generated output directory is a child of the schema root, traversal skips that child directory; explicitly configuring the generated child directory itself as the schema path still fails with `invalid_path`.

This is **not** equivalent to Drizzle's `pull` command. Drizzle does not have a `gen` equivalent because TypeScript infers column types from the schema definition at compile time — no generation step is needed. `grizzle gen` exists because Go's type system cannot perform the same inference. This is **DEVIATION:LANGUAGE**.

```sh
grizzle gen --schema ./schema --out ./schema --package schema
```

Generated source writes must use the same managed-source root safety model as `pull`: canonical root resolution, rejection of symlinked output roots, no-follow file creation/replacement, hardlink and non-regular-file rejection where detectable, path containment under the configured output root, and deterministic overwrite ownership rules for generated files.

Generated source output must also use the shared resource-limit model. `grizzle gen` must enforce per-file generated source byte caps, total generated source byte caps, and total planned write byte caps before staging or publishing `*_gen.go` files. Limit failures return `resource_limit` with redacted diagnostics and must not leave partial generated output.

Generated output filenames must be immediate children of the configured output root and must match the exact safe basename pattern `^[a-z0-9_]+_gen\.go$`. Filenames are lowercased from sanitized Go identifiers or generated package/table identifiers, not raw SQL object names. Absolute paths, path separators, dot segments, empty basenames, unsupported characters, and deterministic filename collisions must fail before staging or overwrite checks.

`grizzle gen` generated files must include this exact ownership header in the emitted prelude position:

```go
// Code generated by grizzle gen v1; DO NOT EDIT.
```

Overwrite rule:

- files with the exact `grizzle gen` managed header may be overwritten by later `grizzle gen` runs
- files without the recognized header are unowned and must fail with `managed_file_overwrite`
- `grizzle gen` must not use the `grizzle pull` header for ownership and must not overwrite files owned by `pull` unless a future shared ownership model is explicitly specified
- the exact header line must appear in the emitted prelude position, immediately before the `package` clause after only permitted UTF-8 BOM handling, build tags, blank lines, and package documentation
- arbitrary pre-package comments containing the header text do not prove ownership; misleading comments in manually authored files must still fail with `managed_file_overwrite`
- generated files must include the header in that exact prelude position, and overwrite tests must cover missing headers, wrong versions, header text in ordinary comments, and otherwise valid files whose header is not in the exact emitted prelude position

### What it generates

For each table definition, `grizzle gen` produces typed table handles, select/insert/update structs, generated column-name constants, and metadata:

**1. `<Table>Table` struct** — typed column handles for use in queries

```go
type UsersTable struct {
    ID        expr.UUIDColumn
    RealmID   expr.UUIDColumn
    Username  expr.StringColumn
    Email     expr.StringColumn
    Enabled   expr.BoolColumn
    CreatedAt expr.TimestampColumn
    DeletedAt expr.TimestampColumn
}

var UsersT = UsersTable{
    ID: expr.NewUUIDColumn(sqlmeta.ColumnMeta{
        Ref:          sqlmeta.ColumnRef{Table: sqlmeta.TableRef{Name: "users"}, Name: "id"},
        GoType:       reflect.TypeOf(uuid.UUID{}),
        Nullable:     false,
        Encoder:      expr.UUIDParamEncoder(),
        SelectionKey: "id",
    }),
    Email: expr.NewStringColumn(sqlmeta.ColumnMeta{
        Ref:          sqlmeta.ColumnRef{Table: sqlmeta.TableRef{Name: "users"}, Name: "email"},
        GoType:       reflect.TypeOf(""),
        Nullable:     true,
        Encoder:      expr.StringParamEncoder(),
        SelectionKey: "email",
    }),
    // ...
}

const (
    UsersColID        = "id"
    UsersColRealmID   = "realm_id"
    UsersColUsername  = "username"
    UsersColEmail     = "email"
    UsersColEnabled   = "enabled"
    UsersColCreatedAt = "created_at"
    UsersColDeletedAt = "deleted_at"
)

func (UsersTable) GrizTableRef() query.TableRef {
    return query.TableRef{Name: "users"}
}

func (UsersTable) GrizSelectAllColumns() []expr.SelectableColumn {
    return []expr.SelectableColumn{UsersT.ID, UsersT.RealmID, UsersT.Username, UsersT.Email, UsersT.Enabled, UsersT.CreatedAt, UsersT.DeletedAt}
}

func (UsersTable) GrizSelectAllFieldKeys() []string {
    return []string{"id", "realmId", "username", "email", "enabled", "createdAt", "deletedAt"}
}

func (UsersTable) GrizCountSource() {}
```

Every generated table handle, generated view handle, and generated read-only alias handle that can appear in a `FROM` clause must implement `GrizSelectAllColumns()` and `GrizSelectAllFieldKeys()` so no-arg `query.Select().From(source)` can mirror Drizzle RC.1's selected-field derivation from tables, views, and aliases. The methods must return RC.1 selected-field order, duplicate-free generated property keys, and caller-owned slices. The property keys are selected-field metadata, not SQL result labels; generic row scanning continues to use SQL labels and `db` tags. Alias handles must regenerate the selected column handles with the alias-bearing `TableRef`, while still preserving read-only status and excluding mutation-target markers.

Every generated table handle and generated view handle that can appear in a `FROM` clause must implement `GrizCountSource()` so it satisfies `query.CountSource`. Generated aliases for countable tables/views must preserve `GrizCountSource()` while returning the aliased `TableRef`.

**2. `<View>View` struct** — typed view handles for use in queries

Generated views use the same source-owned column metadata shape as generated tables for read/query operations, but they must not implement insert/update/delete mutation markers.

```go
type ActiveUsersView struct {
    ID    expr.UUIDColumn
    Email expr.StringColumn
}

var ActiveUsersV = ActiveUsersView{
    ID: expr.NewUUIDColumn(sqlmeta.ColumnMeta{
        Ref:          sqlmeta.ColumnRef{Table: sqlmeta.TableRef{Name: "active_users"}, Name: "id"},
        GoType:       reflect.TypeOf(uuid.UUID{}),
        Nullable:     false,
        Encoder:      expr.UUIDParamEncoder(),
        SelectionKey: "id",
    }),
    Email: expr.NewStringColumn(sqlmeta.ColumnMeta{
        Ref:          sqlmeta.ColumnRef{Table: sqlmeta.TableRef{Name: "active_users"}, Name: "email"},
        GoType:       reflect.TypeOf(""),
        Nullable:     true,
        Encoder:      expr.StringParamEncoder(),
        SelectionKey: "email",
    }),
}

func (ActiveUsersView) GrizTableRef() query.TableRef {
    return query.TableRef{Name: "active_users"}
}

func (ActiveUsersView) GrizSelectAllColumns() []expr.SelectableColumn {
    return []expr.SelectableColumn{ActiveUsersV.ID, ActiveUsersV.Email}
}

func (ActiveUsersView) GrizSelectAllFieldKeys() []string {
    return []string{"id", "email"}
}

func (ActiveUsersView) GrizCountSource() {}
```

View column metadata is generated from schema definitions or `pull` introspection fields such as `IntrospectionViewColumn`. Codegen must derive deterministic view property keys from declared schema DSL keys or the configured introspection casing rules, must reject key collisions before writing generated files, and must populate `ColumnMeta.Ref`, `ColumnMeta.SelectionKey`, Go type, nullability, and encoder/cast metadata for every generated view column. View scan structs use SQL `db` tags exactly like table scan structs. Generated view aliases must regenerate alias-bearing view column handles, preserve `GrizSelectAllColumns()`, `GrizSelectAllFieldKeys()`, and `GrizCountSource()`, and must not gain mutation markers.

Generated view scan structs follow the `<View>Select` naming pattern and use SQL column names in `db` tags:

```go
type ActiveUsersSelect struct {
    ID    uuid.UUID `db:"id"`
    Email *string   `db:"email"`
}
```

For every PostgreSQL table definition, codegen must emit the marker required by PostgreSQL lock `OF` APIs:

```go
func (UsersTable) GrizPGLockTableSource() {}
```

PostgreSQL generated table aliases must preserve `GrizPGLockTableSource()` so `ForUpdate().Of(tableAlias)` can render the active alias. Codegen must not emit this marker for generated PostgreSQL views, CTEs, subqueries, raw table expressions, or non-PostgreSQL handles; custom marker implementations are trusted extensions validated by active query membership.

For every MySQL table definition, codegen must emit the markers required by MySQL-only table APIs:

```go
func (UsersTable) GrizMySQLTableSource() {}
func (UsersTable) GrizMySQLInsertTableSource() {}
```

For MySQL schema definitions with named indexes or unique indexes, codegen must also emit typed index references that satisfy `query.MySQLIndexRef` for index hints. The helper type is emitted once per generated package, for example in a shared generated support file, so multiple generated tables do not duplicate the type or method:

```go
type MySQLIndexName string

func (i MySQLIndexName) MySQLIndexName() string { return string(i) }

const UsersRealmUsernameIdx MySQLIndexName = "users_realm_username_idx"
```

For schema-qualified definitions, generated handles must preserve schema and table as separate identifier parts:

```go
func (AuditLogsTable) GrizTableRef() query.TableRef {
    return query.TableRef{Schema: "audit", Name: "logs"}
}
```

Generated `As(alias)` helpers must preserve `Schema` and `Name` while changing only `Alias`. Codegen must never collapse schema-qualified tables into dotted names such as `"audit.logs"`; query builders quote schema and table separately through `query.TableRef`. All generated alias handles must be distinct read-only types that do not return or embed the base table type. They preserve only read/source markers and regenerated aliased column handles; they must not inherit `GrizInsertTableSource()` or `GrizUpdateTableSource()`.

MySQL generated table aliases must preserve the selectable/read `GrizMySQLTableSource()` marker so table-only MySQL index-hint APIs remain available for aliased tables. Aliases must not preserve `GrizMySQLInsertTableSource()` because Grizzle mutation targets intentionally render only concrete base tables. This is **DEVIATION:INTENTIONAL** fail-fast hardening over RC.1's alias-proxy permissiveness and avoids ambiguous alias mutation SQL. Subqueries, views, CTEs, raw table expressions, and non-MySQL tables must satisfy neither MySQL marker.

Generated table handles must also expose query-builder metadata consumed by SELECT, INSERT, UPDATE, insert-from-select, and MySQL returning-id builders:

```go
func (UsersTable) GrizInsertTableSource()
func (UsersTable) GrizUpdateTableSource()
func (UsersTable) GrizSelectAllColumns() []expr.SelectableColumn
func (UsersTable) GrizSelectAllFieldKeys() []string
func (UsersTable) GrizInsertColumns() []query.InsertColumnMeta
func (UsersTable) GrizUpdateColumns() []query.UpdateColumnMeta
func (UsersTable) GrizTableColumnKeys() []string
func (UsersTable) GrizMySQLReturningIDColumns() []query.MySQLReturningIDColumnMeta // MySQL tables only
```

`query.InsertColumnMeta`, `query.MySQLReturningIDColumnMeta`, and `query.UpdateColumnMeta` are defined by [query-builder.md](./query-builder.md#single-row-multiple-rows). `GrizSelectAllColumns()` / `GrizSelectAllFieldKeys()` support no-arg select-all parity for generated tables/views/aliases and are consumed by `query.Select().From(source)`. `GrizInsertColumns()` returns only insertable columns in deterministic insert order. `GrizTableColumnKeys()` returns every table-definition column key in RC.1 table column order for insert-from-select validation. MySQL generated table handles also emit `GrizMySQLReturningIDColumns() []query.MySQLReturningIDColumnMeta` for the primary-key properties that Drizzle RC.1 `$returningId()` can synthesize. Generated identity, computed, and otherwise non-insertable columns are not returned from `GrizInsertColumns()`; struct/map row inputs that try to set them must fail as unknown or non-insertable fields before SQL execution. Generated metadata methods must return caller-owned slices, or builders must deep-copy the returned slices before use.

Insert/update metadata remains query-owned because it is consumed only by query builders. Generated code may import `query` for `InsertColumnMeta`, `UpdateColumnMeta`, and table-source aliases, while generated concrete column handles use the lower `sqlmeta.ColumnMeta` contract to avoid `expr -> query` import cycles.

Builders use this metadata to validate struct/map rows, reject unknown fields, and render dialect-specific missing-value expressions. Required non-default omissions are not rejected solely for being omitted, because Drizzle RC.1 renders dialect missing-value expressions for omitted insert fields; runtime default/on-update omissions remain unsupported as described below. Insert/update metadata must include the Go type and encoder identity needed by param-capable map/assignment helpers; MySQL returning-id metadata must include the generated table-property key, SQL column name, Go type, encoder identity, nullability, primary-key flag, auto-increment flag, and runtime-default unsupported marker needed by `.ReturningID()` planning and typed property-key scanning. Generated column handles are the preferred source for `SetParam(columnHandle, name)` because they carry the full `query.MutationColumn` contract: type/encoder metadata and base-column ownership. Base generated columns must carry empty `TableRef.Alias`; only read-only alias handles may carry non-empty alias metadata, and those alias handles must not satisfy mutation target interfaces. Generated column constructors must receive or derive full `sqlmeta.ColumnMeta`: schema/table/alias-aware column reference, generated RC.1 property/selection key, Go type, nullability, encoder identity, and placeholder cast behavior. `StaticDefaultSQL` is trusted generated SQL derived from the schema DSL for SQLite-style missing static-default rendering; runtime default/on-update flags are unsupported markers that cause insert builders to fail if an omitted field would require evaluating a runtime hook.
Update/upsert builders use `GrizUpdateColumns()` to detect runtime `$onUpdate` markers. If an UPDATE or UPSERT SET has at least one explicit assignment and Drizzle would add an omitted runtime-on-update column, Grizzle must fail with `unsupported_feature` until a Go runtime hook API exists.

**3. `<Table>Select` / `<View>Select` struct** — for scanning generated table or view query results; nullable columns are pointer types

```go
type UserSelect struct {
    ID        uuid.UUID  `db:"id"`
    RealmID   uuid.UUID  `db:"realm_id"`
    Username  string     `db:"username"`
    Email     *string    `db:"email"`       // nullable → pointer
    Enabled   bool       `db:"enabled"`
    CreatedAt time.Time  `db:"created_at"`
    DeletedAt *time.Time `db:"deleted_at"`  // nullable → pointer
}
```

**4. `<Table>Insert` struct** — for INSERT statements; required fields are plain types, optional non-null fields may use pointers with `omitempty`, and nullable assignable fields use a tri-state wrapper so callers can distinguish omitted from SQL `NULL`

```go
type UserInsert struct {
    ID        *uuid.UUID `db:"id,omitempty"`        // has DefaultRandom → optional
    RealmID   uuid.UUID  `db:"realm_id"`             // required
    Username  string     `db:"username"`              // required
    Email     query.Assign[string] `db:"email"`       // nullable → unset/value/null
    Enabled   *bool      `db:"enabled,omitempty"`     // has Default(true) → optional
    CreatedAt *time.Time `db:"created_at,omitempty"`  // has DefaultNow → optional
}
```

**5. `<Table>ReturningID` struct** — for MySQL `.ReturningID()` / Drizzle `$returningId()` synthesized rows. This struct uses generated table-property keys, not SQL column names, because RC.1 returns table-property-keyed objects for `$returningId()`.

```go
type UserReturningID struct {
    ID int64 `grizzle:"id"` // signed bigint/int64 auto-increment key; tag value is the generated table-property key
}
```

`mysqldb.FromReturningID[T]` and prepared variants use this `grizzle` property-key scanner rather than the generic SQL `db`-tag scanner. The scanner accepts only non-pointer structs with exported `grizzle`-tagged fields when synthesized rows contain keys, treats `grizzle:"-"` as ignored, rejects tag options, requires every synthesized property key to map exactly once, rejects empty/duplicate/unknown tags and extra scan-visible tags, and enforces the generated returning-id Go type/nullability contract. Runtime/default-generated UUID-style primary keys still follow the unsupported runtime-hook and explicit-value rules in [query-builder.md](./query-builder.md#returning); the canonical MySQL generated example uses auto-increment IDs. `mysqldb.ReturningIDRows*` returns lower-level `[]query.ReturningIDRow` maps for dynamic callers.

**6. `<Table>Update` struct** — for UPDATE statements; non-null fields may use pointers so nil fields are omitted from the SET clause regardless of `omitempty`, while nullable fields use the same tri-state wrapper

```go
type UserUpdate struct {
    Username  *string    `db:"username"`
    Email     query.Assign[string] `db:"email"`
    Enabled   *bool      `db:"enabled"`
    DeletedAt query.Assign[time.Time] `db:"deleted_at"`
}
```

Note: the primary key is excluded from `<Table>Update` because it is passed separately in the WHERE clause.

Tri-state assignment contract:

- generated nullable insert/update fields must use `query.Assign[T]` in the initial target; equivalent generated field types are not supported because the reflection inspection contract is owned by the `query` package
- the zero value of `query.Assign[T]` is unset
- `query.Value(v)` creates a concrete value assignment
- `query.Null[T]()` creates an explicit SQL `NULL` assignment
- `query.Unset[T]()` or the zero value creates an omitted field
- `query.Assign[T]` must implement the inspection contract in [types.md](./types.md#db-struct-tag) so reflection-based builders can distinguish unset, null, and value without unsafe field access
- INSERT unset/omitted fields use the dialect-specific missing-value behavior in [query-builder.md](./query-builder.md#single-row-multiple-rows), normally static default handling or dialect-specific nullable/default fallback; runtime hooks fail with `unsupported_feature`
- UPDATE and UPSERT SET unset fields omit the assignment for ordinary columns; omitted runtime `$onUpdate` columns fail with `unsupported_feature` when Drizzle would invoke the hook
- null emits `col = NULL` in UPDATE/UPSERT SET or inserts explicit `NULL` where the dialect permits it
- value emits the normal bound value
- this is required for Drizzle parity because Drizzle can explicitly set nullable columns to `null` while also omitting fields from partial inserts/updates

### Status

Target semantics are Drizzle parity: callers must be able to omit a nullable field or assign explicit SQL `NULL`. The Go API shape is DEVIATION:LANGUAGE because it uses `query.Assign[T]` instead of TypeScript's `T | null | undefined` inference. Implementation remains DEVIATION:GAP until generated nullable insert/update fields, `query.Assign[T]`, `SetStruct`, `DoUpdateSetStruct`, and insert struct handling all implement the tri-state assignment contract. Existing pointer-only nullable assignment behavior is insufficient for Drizzle parity.

### Known limitations

**`json:` struct tags are not generated** — the generator emits only `db:` struct tags. The examples in this file reflect that: all generated structs use only `db:` tags. If your application serialises generated structs to JSON, add `json:` tags manually or embed them in a wrapper struct. A `--json-tags` flag is not yet planned.

| SQL type | Go type | Notes |
|---|---|---|
| `uuid` | `uuid.UUID` | `github.com/google/uuid` |
| `varchar(n)`, `text`, `char(n)` | `string` | |
| `boolean` | `bool` | |
| `smallint` | `int16` | PARITY target; DEVIATION:GAP until generated handle/type coverage is implemented |
| `integer`, PostgreSQL `serial` | `int` | DEVIATION:INTENTIONAL — spec originally said `int32`; Grizzle uses plain `int` (idiomatic Go, pointer-size integer) for consistency with Go conventions. `int32` is a parity target if explicit 32-bit arithmetic is needed in the future. |
| `smallserial` | `int16` | PARITY target; DEVIATION:GAP until generated handle/type coverage is implemented |

| `real` | `float64` | DEVIATION:INTENTIONAL — Drizzle maps `real` to TypeScript `number` (64-bit); Go uses `float64` for consistency with `DoublePrecision` and `FloatBuilder.Default(float64)` |
| `double precision` | `float64` | |
| `timestamp [with time zone]` | `time.Time` | |
| `date` | `time.Time` | Generates `expr.DateColumn` (distinct from `TimestampColumn`) |
| `time [with time zone]` | `string` | Generates `expr.TimeColumn`; Drizzle RC.1 time columns are time-of-day values, not timestamps. A richer Go time-of-day type is DEVIATION:GAP until specified |
| `json` | `map[string]any` or custom type | Default is `map[string]any`; override with `.Type("MyStruct")`; generates `expr.JSONColumn[T]` without JSONB-only containment/existence helpers |

| `bytea` | `[]byte` | Generates `expr.BytesColumn` |
| `inet`, `cidr`, `macaddr`, `macaddr8` | `string` | DEVIATION:INTENTIONAL — Drizzle uses `string` for inet/cidr; typed `netip.Addr`/`netip.Prefix` deferred; `macaddr8` coverage is a parity target if schema support is implemented |
| `interval` | `string` | DEVIATION:INTENTIONAL — PostgreSQL intervals can include months/years with no exact `time.Duration` equivalent; `string` preserves full fidelity |
| `enum` (pg) | `string` | Generates `expr.EnumColumn` |
| `tsvector`, `tsquery` | `string` | GRIZZLE-ONLY/source-generation support; RC.1 recognizes these type names/codecs but does not expose PostgreSQL column-builder helpers for them |
| array | `any` | Generates `expr.ArrayColumn`; typed `[]T` generation remains a separately designed gap. |
| range types (`int4range`, `int8range`, `numrange`, `tsrange`, `tstzrange`, `daterange`) | `string` | GRIZZLE-ONLY — no Drizzle equivalent |

MySQL integer mappings are dialect-specific and must not reuse PostgreSQL `serial` defaults:

| MySQL type | Signed Go type | Unsigned Go type |
|---|---|---|
| `tinyint` | `int8` | `uint8` |
| `smallint` | `int16` | `uint16` |
| `mediumint`, `int`, `integer` | `int32` | `uint32` |
| `bigint` | `int64` | `uint64` |
| `serial` | n/a | `uint64` |

The MySQL `serial` Go mapping is **DEVIATION:LANGUAGE** from RC.1's JavaScript `number`/uint53 surface: Grizzle uses `uint64` to preserve the physical `BIGINT UNSIGNED` range. MySQL auto-increment columns use the declared integer type mapping and unsigned policy from this table. MySQL `.ReturningID()` synthesis starts from driver `int64` metadata and must be checked-converted into `MySQLReturningIDColumnMeta.GoType` before map/scanner output; overflow, sign loss, unsigned values outside the signed metadata range, or incompatible integer metadata fails with redacted `scan_decode` or `unsupported_feature` as specified in [query-builder.md](./query-builder.md#returning), rather than truncating.

## `grizzle pull` — schema definitions from live DB — DEVIATION:GAP (designed)

`grizzle pull` is a separate command from `grizzle gen`. It connects to a live database, introspects the schema, and generates Go schema definition files (`pg.Table(...)` builder calls).

```sh
# Explicit broad-scan opt-in. Prefer schema/table filters for shared databases.
grizzle pull --config ./grizzle.config.yaml --all-schemas
```

This is the Go equivalent of `drizzle-kit pull`. It is the inverse of `grizzle generate` (schema → SQL files), not the inverse of `grizzle gen` (schema definitions → typed structs).

Filesystem-mutating `pull` runs without schema/table filters fail before broad introspection, file writes, or history metadata unless `--all-schemas` / `AllowBroadScan=true` is explicitly supplied. Shared or multi-tenant databases should configure filters instead of broad-scanning, and generated source/artifacts must be reviewed before commit because they may contain sensitive object names or SQL literals copied from the live database.

Introspection exists internally in `kit/introspect`. The pull command — which translates introspection output into Go schema builder calls — is specified but not yet implemented.

See [pull.md](./pull.md) for the authoritative `pull` command contract, including CLI/API shape, overwrite behavior, initial bootstrap migration generation, and `--init`.
